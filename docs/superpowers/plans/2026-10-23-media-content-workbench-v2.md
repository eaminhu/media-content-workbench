## 完整创作流程与后续交付

选题池 → 五维评测/选题复审 → 资料研究与来源 → 大纲/页序 → 正文/逐页文案 → 内容评测和打磨 → 自然语言优化 → 采用确认稿 → 绘图方案 → 封面样张 → 逐页做图 → 文图校正 → 导出。

发布复盘另行读取统一时间窗的真实数据，形成下一轮选题建议。支持从已有稿件进入，缺少前置输入时说明所需材料。

第二阶段补齐正文、来源、版本采用和依赖过期提示。第三阶段接入单页图像生成、单页重做、校正与导出。第四阶段接入发布复盘、历史避重与正式部署。

## 数据和执行契约

- Topic 对应一个候选选题，ContentVersion 保存每次输入及父版本；运行固定引用 versionId。
- WorkflowRun 保存 idempotencyKey、skill 哈希、模型、外部 response ID、状态、输入输出、用量和错误。
- OAuth Responses API 每次必须 store:false、stream:true，并读取到 response.completed 才算成功；请求中断时标记为 needs_attention，不自动再次调用。
- 单次 OAuth 请求禁止隐式重试；未知请求结果需明确呈现，用户核对后自行决定是否新建评测。
- 首阶段使用 SQLite WAL 保存任务与输入；OAuth 评测由网页服务直接流式调用，无独立 worker。服务器部署时重新评估队列、鉴权和存储。
- 图像、SourceEvidence、内容确认和下游失效标记在后续阶段完整实现。

## 质量关口

五维评分只使用用户提供的材料，不冒充事实核验或平台流量预测。分数附理由和行动建议，缺失证据明确列出。历史作品需要用户认可后才能成为质量基准。本地逻辑验证与真实 GPT 质量验证分别记录。
